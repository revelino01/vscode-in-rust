# Extension Compatibility Matrix

This document tracks compatibility of the RustCode Extension Host (`crates/rustcode-ext-host` + `ext-host-js/`) against the VS Code Extension API (`vscode.version = '1.95.0'`).

> **Runtime & Parity Note:** RustCode coordinates extension host state via a pure-Rust JSON/MessagePack `RpcBridge` and live framed stdio subprocess transport `NodeExtHostProcess` (`ContentLengthJson`, `ContentLengthMsgPack`, `NewlineJson`, `from_io`, `JoinSet` half-close EOF draining, `IncomingNotifWork::Barrier` causal fence, `RuntimeLoop` auto-activation & bounded crash recovery) paired with `LanguageFeatureBridge::handle_rpc_message_result` (structured `RpcError` `{ error: { code, message } }`; legacy `handle_rpc_message` retained cleanly for E2E compatibility) and CommonJS shims in `ext-host-js/`. Phase 7 **M1.1–M5** and Phase 8 **M1–M6** deliver Rust ↔ JS RPC parity, `RustCodeContext::create_window()` live bridge attachment, `NotificationsOverlay` / `PromptOverlay`, `TestingSidebarView` (`workbench.view.testing`), contributed `TreeDataProvider` views, `env.getOsInfo` / `process.{exec,spawn,spawnSync}` RPCs (with Unix `setsid`/`setpgid`/`killpg` process-group isolation), all **9** `node-compat` modules (with shared `buffer.js` Base64/UTF-8 codecs & hardened `util.isDeepStrictEqual`), TextMate `.tmLanguage` + `tree-sitter` grammars, real `portable-pty` + `alacritty_terminal` PTY terminals, `wry` OS WebViews (`desktop` feature), `GitCliBackend` SCM, auto-attached `LspClientManager` (incl. `gopls`) + `formatOnSave`, and `.vscode/launch.json` + `DapClient` debugging. The tables below distinguish **`✅ Full`** / **`✅ JS + Rust RPC & UI Parity`** from **`🟡 Live Stdio Sync Note`** (where Node subprocess mode lacks an inline sync transport).
